DeepLiveCam 使用说明

一、根目录日常入口

1_START_DESKTOP_STABLE.cmd
电脑横屏稳定版。保留原功能，不属于手机链路。

2_START_MOBILE_PHONE_FULLSCREEN.cmd
手机竖屏正式入口。已于 2026-10-16 实测：WhatsApp Android 本机预览和对方手机均为竖屏全屏，方向、镜像和实时换脸正常。

根目录只保留以上两个日常入口。历史测试入口统一放在 archive_tests，仅供排障追溯。


二、手机竖屏最终链路

DeepLiveCam 的 OBS Output 窗口
-> 项目内置 FFmpeg 抓取窗口
-> 中央 9:16 裁切、方向校正、1280x720 I420 / 24 fps
-> Frida 注入固定 API 37 AVD 的 Emulated Camera HAL
-> Front / 270 度 / 仅 1280x720
-> 官方 WhatsApp Android

注意：本链路不启动 OBS 软件。“OBS Output”只是 DeepLiveCam 的 OpenCV 输出窗口名称。

已经省略且不得重新加入日常链路：
OBS Virtual Camera、DroidCam、WeCam、VCam、BlueStacks、MEmu。
这些组件会造成 640x480 回退、方向语义错误、黑边、黑屏或不稳定，并不能提高当前链路质量。


三、日常启动

1. 插入摄像头。
2. 运行 2_START_MOBILE_PHONE_FULLSCREEN.cmd。
3. 脚本会自动启动并校验 AVD、Camera HAL、Frida、DeepLiveCam、实时桥接和 WhatsApp。
4. 看到 RESULT: READY 后，在 WhatsApp 内拨打视频。

通话期间只保留模拟器内 QuickQ 连接，关闭电脑端 QuickQ。DeepLiveCam、ADB、Frida 和 FFmpeg 都是本机链路，不需要电脑端 VPN；两端同时连接会形成双层 VPN，增加抖动、丢包和延迟。需要 Git 拉取或电脑端下载时，先结束通话，再单独连接电脑端 QuickQ。启动脚本检测到电脑 QuickQ 与 Android VPN 同时活动时会输出 WARNING，但不会擅自关闭软件。

第一次启动或模拟器被完全关闭后，需要执行约 30–90 秒的无快照冷启动，具体取决于磁盘和系统缓存。日常使用不要反复关闭模拟器；入口会复用已经运行的固定 AVD，后续启动会明显更快。writable Camera HAL 模式不能安全使用 Quick Boot，脚本会主动禁用快照，避免黑屏和 ADB offline 卡住。

脚本会先拒绝错误环境，不会静默降级到 4:3：
- Windows 必须检测到状态正常的摄像头；未插摄像头时立即停止。
- 实体摄像头按设备名称选择，不使用容易因虚拟摄像头安装顺序变化的数字编号。
- AVD 名称必须是 DeepLiveCam_HAL_Test_API37。
- Android 指纹必须与已验证的 API 37 镜像完全一致。
- Camera HAL 文件 SHA-256 必须完全一致。
- 前置摄像头必须报告 Front / 270 度。
- Camera HAL 只能向 WhatsApp 提供 1280x720 流。
- Frida 固定为 17.23.3。

启动报告保存到 logs\mobile_phone_start_时间.txt。
实时桥接日志保存到 logs\mobile_hal_bridge_live.log 和 .err.log。

已固化的启动保护：writable HAL 模式禁用 Quick Boot 快照；自动清理 ADB offline；按设备名称选择实体摄像头；Python 输出固定 UTF-8；FFmpeg 必须取得 DeepLiveCam 首帧后才允许启动 WhatsApp；窗口抓取短暂中断时自动重连。不要删除这些检查来缩短表面启动时间。


四、新电脑一次性部署

Git 只同步代码。以下大文件目录不会进入 Git：python、ffmpeg、models、source_faces。全新电脑必须先从完整 DeepLiveCam 安装包恢复 python、ffmpeg 和 models；source_faces 只放用户自己的源图。已经具备这些目录的另一台电脑可以直接拉取代码。

1. 准备完整 DeepLiveCam 基础运行包，确认 python\python.exe、ffmpeg\bin\ffmpeg.exe、HyperSwap、InSwapper 和 InsightFace 模型存在。
2. 安装 Android Studio / Android SDK，并包含：
   system-images;android-37.0;google_apis;x86_64，必须是 revision 6。
3. 在 PowerShell 运行：
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\mobile_phone\setup_mobile_phone.ps1
4. 等脚本完成固定 AVD、Camera HAL 配置、Frida 运行时和测试视频部署。
5. 将换脸源图放入 source_faces。默认优先 current_test_source.jpg，也可设置 DEEPLIVECAM_SOURCE_FACE 指向其它图片。
6. 在该 AVD 内手动安装官方 WhatsApp，并由用户完成一次登录。
7. 如当地网络需要 VPN，由用户在 AVD 内完成一次 VPN 登录和 Android 授权。
8. 以后只运行 2_START_MOBILE_PHONE_FULLSCREEN.cmd。

无法由 Git 自动迁移的用户数据只有换脸源图、WhatsApp 登录和 VPN 授权。程序配置、版本检查和摄像头参数由脚本完成；如果直接迁移完整项目目录，source_faces 中的图片会随目录保留。

不要升级或替换 API 37 系统镜像、Camera HAL 或 Frida 后继续强行运行。硬编码帧结构只对上述指纹和 HAL 哈希有效；版本漂移时启动脚本会主动停止。


五、画面取舍

当前输出采用横向源画面的中央 9:16 区域，以换取对方手机真正竖屏全屏。它不会拉伸人物，但会裁掉左右画面，因此摄像头距离和构图仍需按竖屏取景调整。

默认 low_latency 模式使用 24 fps 和 bilinear 缩放，优先降低延迟；quality 模式使用 24 fps 和 bicubic 缩放，边缘更清晰但负载略高。中央 404x720 有效区域需要放大，因此只改输出分辨率不能凭空增加细节；真正进一步提升画质，需要提高 DeepLiveCam 的源帧分辨率或改为直接帧传输。

未来若优化性能，唯一合理方向是让 DeepLiveCam 直接输出 I420 帧，省掉窗口抓取和 FFmpeg。该优化必须先做独立对照测试；在达到当前画质、方向、稳定性和远端全屏效果前，不得替换现有正式链路。


六、历史测试

历史脚本和失败方案结论位于 archive_tests。它们不属于日常使用流程，不应从该目录启动，除非专门进行回归排障。
