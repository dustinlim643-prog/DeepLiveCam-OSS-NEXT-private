DeepLiveCam OSS_NEXT 使用说明

一、当前结论

正式可用模式是电脑横屏：
DeepLiveCam OBS Output -> OBS -> DroidCam Video -> WhatsApp Desktop

手机全屏竖屏目标尚未实现。
入口 6 只是竖屏裁切备用模式，不是真实手机对手机的全屏效果。


二、根目录入口

1_START_DESKTOP_STABLE.cmd
正式日常入口，1280x720 / 30fps，WhatsApp 选择 DroidCam Video。

3_STOP_ALL.cmd
停止 DeepLiveCam、OBS 和项目后台进程。

4_DIAGNOSTICS_MENU.cmd
1：WhatsApp 链路诊断
2：稳定性快照
3：30 秒性能报告
4：最近健康日志

5_SETUP_NEW_DEVICE.cmd
新设备一次性安装/检查入口，日常不运行。

6_START_MOBILE_CROP_BACKUP.cmd
备用入口。保持兼容的 1280x720 流，在中间放置 405x720 竖屏内容；会缩小有效画面并留下黑区。

编号不重排，避免已有快捷方式失效。


三、正式模式启动

1. 运行 1_START_DESKTOP_STABLE.cmd。
2. 等待 DeepLiveCam、OBS 和 OBS Output 窗口出现。
3. 在 DeepLiveCam 确认源图、摄像头，然后启动 Live。
4. 确认 OBS 预览有实时换脸画面。
5. WhatsApp Desktop 选择 DroidCam Video。

重要：不要最小化 OBS Output。它是 OBS 的窗口捕获源，最小化会导致 OBS、虚拟摄像头和通话画面变黑。

无画面时按此顺序处理：
1. 运行 3_STOP_ALL.cmd。
2. 重新运行 1_START_DESKTOP_STABLE.cmd。
3. 等 OBS Output 和 OBS 预览都有画面后，再打开 WhatsApp。
4. 仍异常时运行 4_DIAGNOSTICS_MENU.cmd，选择 1。


四、稳定基准参数

摄像头输入：1280x720 / 30fps，MJPG
OBS profile / scene：DeepLiveCam
OBS 捕获：OBS Output:HighGUI class:python.exe，WGC
OBS 画布 / 输出：1280x720 / 30fps
OBS 有效区域：970x546，X=155，Y=86，Lanczos
OBS 锐化：0.18
OBS contrast：0.06
OBS saturation：0.04
OBS DroidCam AutoStart：true
WhatsApp 摄像头：DroidCam Video

主模型：HyperSwap 256
质量档位：low_latency
Face Enhancer：None
XSeg：关闭
GPEN：关闭
Poisson Blend：关闭
颜色迁移强度：0.25
DeepLiveCam 锐化：0.18
face_fit_scale：1.06
face_mask_scale：0.45
face_mask_blur：23
live_face_smooth：0.25
similar_face_distance：1.5
Mouth Mask：0

调坏后先恢复以上数值。不要同时修改多个变量。


五、嘴部微调

位置：DeepLiveCam 主界面 -> Refinement / 细节调整 -> Mouth Mask。

稳定值：0
只按顺序测试：10 -> 15 -> 20，暂时不要超过 20。

每档测试：
正常说话 20 秒；露牙 10 秒；撅嘴 5 秒；轻微左右转头说话 10 秒。

判断：
数值增大通常会保留更多真实嘴部和牙齿动态，但身份相似度可能下降。
出现嘴角断层、嘴周发糊或嘴巴不像源图时，立即回退上一档。


六、源图标准

优先使用：正脸、头部水平、镜头与眼睛同高、嘴唇自然闭合、无遮挡、光线均匀、脸颊和下巴完整、真实皮肤纹理。

避免使用：大眼滤镜、尖下巴、过度瘦脸、丰唇高光、露齿、撅嘴、重度磨皮、近距离广角自拍、头发遮住脸部边缘。

生成规格：1:1，1024x1024 或更高；身份相似优先；自然椭圆脸；不放大眼睛、不缩鼻、不丰唇。

给 AI 的简短提示词：
请基于我提供的已授权照片生成真实照片级换脸源图。保持人物身份；严格正脸；头部水平；镜头与眼睛同高；自然眼睛和瞳孔；嘴唇轻闭、不露齿、不撅嘴；保留自然脸宽和下巴长度；不要瘦脸、大眼、丰唇或重度磨皮；完整显示额头、双侧脸颊和下巴；柔和正面光；简单背景；1:1，1024x1024。


七、手机全屏方案测试结论

以下路线均已完成关键验证，不再重复：

BlueStacks：能读取换脸画面，但 Camera HAL 方向语义不符合目标，远端仍是横屏容器。

MEmu + WeCam：MEmu 没有打开 WeCam WDM 摄像头，Android 端黑屏。

官方 AVD + DroidCam：能报告 Front/90，但 WhatsApp 实际请求 640x480，远端不能铺满手机竖屏。

官方 AVD + WeCam：能报告 Front/90，也能传输实时换脸画面；WhatsApp 仍固定请求两路 640x480，实际通话有明显上下黑区，最终失败。

Root、Magisk、LSPosed、修改版 WhatsApp：因稳定性、维护和账号风险取消。

核心结论：调整 OBS 画布、WeCam 尺寸或模拟器窗口，只能改变视频帧里的构图，不能改变 WhatsApp 的远端布局策略。

新方案准入条件：
1. 必须先证明它能改变 Camera HAL / Camera2 流配置或 WhatsApp 的设备与布局判定。
2. 如果预检仍是 Front/90 + WhatsApp 640x480，直接停止。
3. 只改变裁切、黑边或桥接软件，不算新方案。
4. 预检通过后才允许安装、登录和进行一次真实通话验收。

纯软件方向只剩自定义 AOSP/Cuttlefish Camera HAL，属于独立开发项目，不纳入日常入口。


八、诊断与性能

日志目录：logs

通话异常：4_DIAGNOSTICS_MENU.cmd -> 1
完整快照：4_DIAGNOSTICS_MENU.cmd -> 2
性能测试：4_DIAGNOSTICS_MENU.cmd -> 3
最近健康状态：4_DIAGNOSTICS_MENU.cmd -> 4

关键指标：
process_fps 低或 queue_in 长期满：本地处理跟不上。
camera_fps 低：摄像头输入或驱动问题。
miss_rate 高：侧脸、遮挡、距离或掉脸问题。
avg_ms_detect 高：检测/追踪瓶颈。
avg_ms_swap 高：HyperSwap 瓶颈。
avg_ms_enhance 高：增强器负担过重。


九、新设备迁移

Git 只同步代码、脚本和可提交配置，不同步模型、Python/OBS 完整运行环境、驱动和 WhatsApp 登录状态。

ffmpeg\bin\ffmpeg.exe
obs-studio\bin\64bit\obs64.exe
models\hyperswap_1a_256.onnx
