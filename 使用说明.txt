DeepLiveCam 使用说明

一、根目录日常入口

1_START_DESKTOP_STABLE.cmd
电脑横屏稳定版。保留原功能，不属于手机链路。

2_START_MOBILE_PHONE_FULLSCREEN.cmd
手机竖屏正式入口。已于 2026-10-16 实测：WhatsApp Android 本机预览和对方手机均为竖屏全屏，方向、镜像和实时换脸正常。

根目录只保留以上两个日常入口。历史测试入口统一放在 archive_tests，仅供排障追溯。


二、手机竖屏最终链路

DeepLiveCam 的 OBS Output 窗口
-> 项目内置 FFmpeg 抓取窗口
-> 中央 9:16 裁切、方向校正、1280x720 I420 / 15 fps
-> Frida 注入固定 API 37 AVD 的 Emulated Camera HAL
-> Front / 270 度 / 仅 1280x720
-> 官方 WhatsApp Android

注意：本链路不启动 OBS 软件。“OBS Output”只是 DeepLiveCam 的 OpenCV 输出窗口名称。

已经省略且不得重新加入日常链路：
OBS Virtual Camera、DroidCam、WeCam、VCam、BlueStacks、MEmu。
这些组件会造成 640x480 回退、方向语义错误、黑边、黑屏或不稳定，并不能提高当前链路质量。


三、日常启动

1. 插入摄像头。
2. 运行 2_START_MOBILE_PHONE_FULLSCREEN.cmd。
3. 脚本会自动启动并校验 AVD、Camera HAL、Frida、DeepLiveCam、实时桥接和 WhatsApp。
4. 看到 RESULT: READY 后，在 WhatsApp 内拨打视频。

脚本会先拒绝错误环境，不会静默降级到 4:3：
- AVD 名称必须是 DeepLiveCam_HAL_Test_API37。
- Android 指纹必须与已验证的 API 37 镜像完全一致。
- Camera HAL 文件 SHA-256 必须完全一致。
- 前置摄像头必须报告 Front / 270 度。
- Camera HAL 只能向 WhatsApp 提供 1280x720 流。
- Frida 固定为 17.23.3。

启动报告保存到 logs\mobile_phone_start_时间.txt。
实时桥接日志保存到 logs\mobile_hal_bridge_live.log 和 .err.log。


四、新电脑一次性部署

1. 安装 Android Studio / Android SDK，并包含：
   system-images;android-37.0;google_apis;x86_64，必须是 revision 6。
2. 在 PowerShell 运行：
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\mobile_phone\setup_mobile_phone.ps1
3. 等脚本完成固定 AVD、Camera HAL 配置、Frida 运行时和测试视频部署。
4. 将换脸源图放入 source_faces。默认优先 current_test_source.jpg，也可设置 DEEPLIVECAM_SOURCE_FACE 指向其它图片。
5. 在该 AVD 内手动安装官方 WhatsApp，并由用户完成一次登录。
6. 如当地网络需要 VPN，由用户在 AVD 内完成一次 VPN 登录和 Android 授权。
7. 以后只运行 2_START_MOBILE_PHONE_FULLSCREEN.cmd。

无法由 Git 自动迁移的用户数据只有换脸源图、WhatsApp 登录和 VPN 授权。程序配置、版本检查和摄像头参数由脚本完成；如果直接迁移完整项目目录，source_faces 中的图片会随目录保留。

不要升级或替换 API 37 系统镜像、Camera HAL 或 Frida 后继续强行运行。硬编码帧结构只对上述指纹和 HAL 哈希有效；版本漂移时启动脚本会主动停止。


五、画面取舍

当前输出采用横向源画面的中央 9:16 区域，以换取对方手机真正竖屏全屏。它不会拉伸人物，但会裁掉左右画面，因此摄像头距离和构图仍需按竖屏取景调整。

未来若优化性能，唯一合理方向是让 DeepLiveCam 直接输出 I420 帧，省掉窗口抓取和 FFmpeg。该优化必须先做独立对照测试；在达到当前画质、方向、稳定性和远端全屏效果前，不得替换现有正式链路。


六、历史测试

历史脚本和失败方案结论位于 archive_tests。它们不属于日常使用流程，不应从该目录启动，除非专门进行回归排障。
