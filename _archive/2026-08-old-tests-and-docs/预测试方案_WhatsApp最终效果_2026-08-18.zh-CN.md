# 预测试方案：WhatsApp 最终效果

更新时间：2026-08-18

## 当前目标

最终验收不是 DeepLiveCam 本地画面，也不是 OBS 本地预览，而是：

```text
对方 WhatsApp 手机端看到的画面
```

DeepLiveCam、OBS、DroidCam、WhatsApp 各自负责不同问题，测试时必须分层判断。

## 当前核心链路

```text
DeepLiveCam 单图实时换脸
  -> OBS Output 窗口
  -> OBS 捕获/缩放/轻调色
  -> DroidCam Virtual Output
  -> WhatsApp Desktop 选择 DroidCam Video
  -> 对方手机端观看
```

## 不覆盖原则

当前已经有一个静止效果较好的质量配置，不直接覆盖。

保留两套入口：

```text
1_START.cmd              质量模式
1_START_LOW_LATENCY.cmd  流畅模式
2_STOP.cmd               停止
3_CHECK.cmd              自检
```

## 两套模式

### 质量模式

入口：

```text
1_START.cmd
```

用途：

```text
看静止真实度、脸型、边缘、颜色、嘴部、整体观感。
```

配置：

```text
HyperSwap 256
XSeg 开
quality preset：high_quality
Face Enhancer：关
OBS：1280x720 / 30fps
摄像头：1920x1080 / 30fps
WhatsApp：DroidCam Video
```

### 流畅模式

入口：

```text
1_START_LOW_LATENCY.cmd
```

用途：

```text
判断卡顿是否主要来自 XSeg / high_quality / 当前硬件。
```

配置：

```text
HyperSwap 256
XSeg 关
quality preset：low_latency
Face Enhancer：关
OBS：1280x720 / 30fps
摄像头：1920x1080 / 30fps
WhatsApp：DroidCam Video
```

判断规则：

```text
流畅模式明显更顺：瓶颈主要在 XSeg/high_quality/当前硬件。
流畅模式仍然很卡：当前硬件不足，等 5070Ti/4080 再做最终判断。
流畅模式顺但边缘差：说明质量模式方向正确，硬件升级后应回到质量模式。
```

## 分层职责

### DeepLiveCam 负责

```text
身份相似度
脸型贴合
嘴部/眼部稳定
边缘融合
动态追踪
实时处理 FPS
```

如果本地 OBS Output 里已经一眼假，问题优先在 DeepLiveCam / 源图 / 模型 / mask。

### OBS 负责

```text
画面裁切比例
整体亮度
对比度
饱和度
轻微锐化
让脸和背景更统一
```

OBS 不能真正解决脸型不贴、嘴部错位、严重穿帮。OBS 的目标是让整体画面更均衡，而不是把换脸模型变强。

### DroidCam 负责

```text
把 OBS 画面变成 WhatsApp 更容易识别的虚拟摄像头。
```

DroidCam 是兼容层，不负责提升换脸质量。

### WhatsApp 负责

```text
最终编码、传输、降码率、远端显示。
```

如果本地 OBS 清楚，但对方 WhatsApp 糊，需要排查 WhatsApp 设置、网络、设备性能和通话压缩。

## WhatsApp 模糊排查

不要直接假设一定是压缩。按下面顺序排查。

### 1. WhatsApp 设置

检查：

```text
WhatsApp Desktop 已更新到最新版。
设置 -> 视频和语音 -> 摄像头：DroidCam Video。
通话中左下角摄像头菜单仍然是 DroidCam Video。
不要选择 4k Camera。
不要选择 OBS Virtual Camera。
```

注意：

```text
WhatsApp 的“媒体上传质量/HD”主要针对文件发送，不等于视频通话质量设置。
视频通话通常没有手动固定码率或固定 1080p 的按钮。
```

### 2. 网络

检查：

```text
电脑尽量使用有线网络或稳定 5GHz Wi-Fi。
手机端也使用稳定 Wi-Fi。
测试时关闭下载、网盘同步、游戏、直播、其它占带宽程序。
同一次测试持续 3-5 分钟，观察是否从清晰变糊。
```

判断：

```text
双方画面都糊、偶尔清晰：更像网络/WhatsApp 自适应码率。
只有我方换脸画面糊：更像 OBS/DroidCam/DeepLiveCam 输出链路。
对方画面也糊：不能只怪换脸软件。
```

### 3. 本地链路对比

同一时间看三层：

```text
DeepLiveCam OBS Output
OBS 预览
对方 WhatsApp 手机端
```

判断：

```text
OBS Output 糊：DeepLiveCam/源图/模型问题。
OBS Output 清楚，OBS 预览糊：OBS 缩放/滤镜问题。
OBS 预览清楚，对方手机糊：DroidCam/WhatsApp/网络问题。
```

### 4. 与非换脸画面对比

必要时做一次基准测试：

```text
OBS 放一个清晰文字/色块测试画面
DroidCam 输出给 WhatsApp
对方手机看是否仍然糊
```

如果文字/色块也糊，说明 WhatsApp/DroidCam/网络是主要瓶颈。

如果文字/色块清楚，换脸画面糊，说明问题在 DeepLiveCam 输出或 OBS 滤镜。

## OBS 后处理方向

当前 OBS 目标不是“强美颜”，而是让整体更统一。

优先测试：

```text
轻微降低对比度
轻微降低饱和度
轻微提高亮度/Gamma
轻微锐化
不要强磨皮
不要强锐化
```

本地 OBS 看起来过锐或过艳，进入 WhatsApp 后更容易假。宁可本地稍微柔和，让远端压缩后更自然。

## 网络异常预防记录

这是后续优化，不在当前轮立刻实现：

```text
低 FPS 时自动降级到流畅模式。
检测掉帧严重时自动关闭 XSeg。
DeepLiveCam 掉脸时保留上一帧短时间输出，避免闪烁。
OBS/DroidCam 输出保持固定 720p/30fps，避免设备重新协商。
记录每次通话的 FPS、GPU、网络状态和远端观感。
```

## 当前预测试步骤

### 第 1 轮：质量模式

```text
启动：1_START.cmd
测试时间：3 分钟
动作：正脸静止、正常说话、轻微转头
记录：本地 OBS Output、OBS 预览、对方 WhatsApp 手机端
```

验收：

```text
静止脸型是否真实。
边缘是否稳定。
嘴唇颜色是否自然。
对方手机是否明显糊。
```

### 第 2 轮：流畅模式

```text
启动：1_START_LOW_LATENCY.cmd
测试时间：3 分钟
动作同上
```

验收：

```text
FPS 是否明显提升。
对方手机是否明显更顺。
边缘是否明显变差。
```

### 第 3 轮：WhatsApp 糊排查

只在前两轮仍觉得远端明显糊时做：

```text
保持 OBS/DroidCam/WhatsApp。
用 OBS 输出非换脸清晰测试画面。
让对方手机观察是否仍糊。
```

验收：

```text
非换脸画面也糊：优先查 WhatsApp/网络/DroidCam。
非换脸画面清楚：回到 DeepLiveCam/OBS 画面质量优化。
```

## 当前阶段不做

```text
不训练模型。
不改 4K。
不直接覆盖质量模式。
不同时改源图、mask、OBS、XSeg。
不因为当前硬件 FPS 低就否定最终方案。
```

## 参考信息

- WhatsApp 官方帮助有视频通话特效/滤镜说明，但未提供固定通话码率或强制 HD 视频通话设置。
- WhatsApp 官方通话排障提到需要检查网络、防火墙和连接。
- 手机厂商支持文档普遍把视频通话模糊/冻结归因到网络弱、光线不足、镜头状态、设备性能和应用适配。
